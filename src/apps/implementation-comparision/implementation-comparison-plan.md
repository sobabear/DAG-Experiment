AI 코드 생성 툴(Claude Code, Cursor, Copilot 등)을 비교 평가할 때, **'단일 대형 프로젝트(유기적 조합)'** 방식과 **'개별 특화 퀘스트(단독 검증)'** 방식을 병행하는 것은 코드 일관성·컨텍스트 유지력·특수 능력치(환각 감지, 최적화 등)를 동시에 검증할 수 있는 최적의 실험 설계입니다.

실험을 즉시 시작하실 수 있도록 **[1] 객관적 평가 잣대(Rubric)**, **[2] 유형 A 요구사항 (단일 프로젝트 20개)**, [3] 유형 B 요구사항 (독립 미션 20개)을 체계적으로 정리해 드립니다.

## 1. AI Code 툴 종합 평가 잣대 (Evaluation Rubric)

각 AI 툴이 정답 코드를 제출했을 때, 아래 5개 차원(총점 100점 만점)으로 점수화하면 정량적 비교가 가능합니다.

| 평가 항목 | 배점 | 세부 평가 내용 | 측정 방식 및 팁 |
| --- | --- | --- | --- |
| **기능 정확성 (Accuracy)** | 30점 | 요구사항 명세를 100% 만족하는가? 정상 동작하는가? | 단위 테스트 통과율, 엣지 케이스 처리 여부 |
| **환각 및 안전성 (Hallucination)** | 20점 | 존재하지 않는 API/라이브러리를 생성하거나 잘못된 구문을 썼는가? | 컴파일/런타임 에러 수, 가짜 패키지 사용 여부 |
| **코드 품질 & 설계 (Quality)** | 20점 | 가독성, 모듈화, 타입 안전성, 디자인 패턴이 적절한가? | 정적 분석 도구 점수, 하드코딩 유무, DI 적용 여부 |
| **예외 및 안정성 (Robustness)** | 15점 | 비정상 입력, 네트워크 에러, 동시성 이슈를 방어했는가? | Null/Nil 처리, Try-Catch 구조, Thread Safety |
| **프롬프트 추종 & 효율성 (Efficiency)** | 15점 | 한 번에 완수했는가? (추가 수정 요청 횟수 및 실행 속도) | 성공까지 걸린 프롬프트 턴 수(Iterative count) |

> 💡 **주요 기록 지표**:
> * **First-prompt Success**: 단 한 번의 프롬프트로 완벽히 작동했는가?
> * **Hallucination Count**: 존재하지 않는 함수/라이브러리를 호출해 에러가 발생한 횟수
> * **Fix Effort**: 에러 발생 시 AI 스스로 디버깅하여 수정하는 데 걸린 턴 수

## 2. [유형 A] 단일 프로젝트 요구사항 (20개 유기적 세부 기능)

* **프로젝트 목표**: **"실시간 필터링 및 오프라인 캐싱 지원 스마트 노트/작업 관리 시스템"**
* **특징**: 단순 CRUD를 넘어 아키텍처, 비동기, 상태 관리, 동시성 제어까지 종합적으로 요구합니다.

### 🏗️ 기본 구조 & 데이터 레이어

1. **데이터 모델 정의**: `Note` 모델(ID, 제목, 내용, 태그 목록, 우선순위[High/Med/Low], 완료 여부, 생성일, 수정일)을 불변(Immutable) 상태로 구현할 것.
2. **아키텍처 분리**: Presentation, Domain, Data 레이어로 관심사를 분리하고 인터페이스 기반 설계할 것.
3. **의존성 주입(DI)**: Repository 및 Logger 인터페이스를 정의하고, 외부에서 주입받는 DI 컨테이너 또는 생성자 주입을 구현할 것.
4. **로컬 데이터 저장**: 파일 시스템 또는 로컬 DB에 JSON/SQLite 형태로 데이터를 영속화(Persistence)할 것.
5. **인메모리 캐시**: 자주 조회되는 노트 10개를 LRU(Least Recently Used) 알고리즘으로 메모리 캐싱하는 레이어를 추가할 것.

### ⚡ 비동기 & 비즈니스 로직

6. **비동기 CRUD**: 데이터 읽기/쓰기 작업을 비동기(Async/Await 또는 Promise)로 처리하여 I/O 블로킹을 방지할 것.
7. **실시간 검색 (Debounce)**: 제목 및 내용 대상 실시간 검색 구현 시 300ms 디바운스(Debounce)를 적용할 것.
8. **복합 필터링 Engine**: 태그, 우선순위, 완료 여부를 다중 조건(AND/OR)으로 조합해 필터링하는 로직을 구현할 것.
9. **동적 정렬**: 생성일순, 우선순위순, 제목순(오름차순/내림차순) 동적 정렬 기능을 제공할 것.
10. **반복 작업 계산기**: 특정 주기로 반복되는 노트의 '다음 마감일'을 계산하는 날짜 알고리즘을 구현할 것.

### 🛡️ 에러 핸들링 & 안전성

11. **유효성 검사기 (Validator)**: 제목 빈값 불가(최대 50자), 태그 최대 5개 제한을 검증하는 독립 Validator를 구현할 것.
12. **커스텀 에러 처리**: `StorageError`, `ValidationError` 등 커스텀 에러 타입을 정의하고 에러 상황별 디버깅 메시지를 매핑할 것.
13. **스레드 안전성 (Thread Safety)**: 캐시 및 데이터 수정 시 Race Condition이 발생하지 않도록 동시성 제어(Lock/Actor/Mutex)를 적용할 것.
14. **원자성(Atomicity) 보장**: 여러 노트를 일괄 삭제할 때 하나라도 실패하면 전체 작업이 롤백되는 가상 트랜잭션을 구현할 것.

### 🔄 상태 관리 & 데이터 변환

15. **상태 머신 (UI/State)**: Loading, Success, Empty, Error 상태를 독립적으로 관리하고 알리는 Observer/Subscription 패턴을 구현할 것.
16. **페이지네이션**: 대용량 데이터 대응을 위해 20개 단위로 커서 기반(Cursor-based) 페이지네이션을 처리할 것.
17. **JSON Export/Import**: 전체 데이터를 JSON 파일로 내보내고 불러오는 기능 구현 (손상된 JSON 수신 시 복구 에러 처리 포함).

### 🧪 모니터링 & 테스트

18. **타임스탬프 로거**: 모든 데이터 변경(CRUD) 시 작업 종류와 타임스탬프를 기록하는 Logger 서비스 구현.
19. **단위 테스트 (Unit Test)**: 데이터 파싱, 검색/필터링 로직, LRU 캐시에 대한 단위 테스트 코드를 작성할 것.
20. **Mock 데이터 생성기**: 테스트를 위해 100개의 임의 노트 데이터를 즉시 생성을 돕는 Factory 함수를 구현할 것.

## 3. [유형 B] 20개 개별 독립 요구사항 (특수 역량 평가용)

독립적인 20개의 단독 프롬프트입니다. 특히 **4번, 5번, 6번**은 AI의 **할루시네이션(환각) 함정 테스트**입니다.

| 번호 | 테스트 영역 | 상세 프롬프트 요구사항 | 평가 목적 |
| --- | --- | --- | --- |
| **1** | **알고리즘** | 중첩 깊이가 불분명한 복잡한 JSON 객체에서 특정 키를 찾아 모든 경로(Path) 배열을 반환하는 재귀 함수 작성 | 복잡한 뇌지컬 구현력 |
| **2** | **동시성** | 동시에 실행되는 비동기 작업의 수를 최대 N개로 제한하는 Queue 클래스 구현 | 동시성 제어 능력 |
| **3** | **스트리밍** | 1GB 크기의 대용량 CSV 파일을 메모리에 전체 로드하지 않고 스트리밍 방식으로 파싱하는 함수 작성 | 메모리 효율적 설계 |
| **4** | **[환각 함정 1]** | 언어 표준에 존재하지 않는 가짜 메서드(예: `Array.prototype.sortByGroupAndSum`)를 사용해 코드를 작성해 달라고 요청 | 없는 API를 지어내는지 검증 |
| **5** | **[환각 함정 2]** | 구버전(Deprecated) API 함수 이름을 제시하고 최신 사양에 맞게 구현해달라고 지시 | 최신 사양 인지 여부 |
| **6** | **[환각 함정 3]** | 가상의 외부 라이브러리 `fast-crypto-parser-v2`를 `import`하여 암호화 로직을 짜달라고 요청 | 가짜 패키지 무지성 import 방지 |
| **7** | **리팩토링** | 10개 이상의 중첩 `if-else`문으로 구성된 코드 스파게티를 제공하고 Strategy 패턴으로 리팩토링 | 코드 디자인 및 패턴 감각 |
| **8** | **보안** | 사용자 입력 문자열에서 SQL Injection 및 XSS 위험을 방지하는 새니타이징(Sanitize) 유틸리티 작성 | 보안 의식 및 에스케이핑 |
| **9** | **메모리 최적화** | 순환 참조(Circular Reference)로 인해 메모리 누수가 발생하는 코드를 제공하고 문제 진단 및 수정 | 메모리 디버깅 능력 |
| **10** | **상태 머신** | 결제 상태(Pending → Processing → Completed/Failed/Refunded) 흐름을 강제하는 유닛 상태 머신 작성 | 잘못된 상태 전이 방어 |
| **11** | **타입 시스템** | 컴파일 타임에 타입 안전성을 100% 보장하는 제네릭 기반 Event Emitter 작성 | Advanced Type 활용력 |
| **12** | **순수 유틸리티** | 외부 라이브러리 없이 타이머 기반으로 동작하는 `debounce`와 `throttle` 함수 구현 | 기초 CS 및 타이머 이해도 |
| **13** | **수학적 검증** | 신용카드 번호 유효성을 검증하는 Luhn 알고리즘 구현 | 정규식 및 수식 구현력 |
| **14** | **자료구조** | 문자열 자동완성을 위한 트라이(Trie) 자료구조 구현 및 Prefix 추천 검색 함수 작성 | 핵심 자료구조 직접 구현력 |
| **15** | **네트워크 재시도** | 지수 백오프(Exponential Backoff) 및 Jitter 알고리즘을 적용한 비동기 API 재시도(Retry) 함수 작성 | 네트워크 실패 대응 설계 |
| **16** | **Rate Limiter** | Token Bucket 알고리즘 기반으로 초당 요청 횟수를 제한하는 Rate Limiter 구현 | 시스템 아키텍처 기초 |
| **17** | **Diff 알고리즘** | 두 개의 객체(Object)를 비교하여 변경 사항(Added, Modified, Deleted)을 추적하는 Delta 반환 함수 작성 | 데이터 비교 알고리즘 |
| **18** | **테스트 코드** | 경계값(0, 음수, MAX_SAFE_INTEGER, null)이 포함된 함수에 대해 모든 경계 조건을 테스트하는 단위 테스트 작성 | 테스트 케이스 커버리지 |
| **19** | **의존성 역전** | 하드코딩된 API 통신 코드를 프로토콜/인터페이스 기반 추상화로 변환 | SOLID 원칙 준수 여부 |
| **20** | **환경 구축** | 애플리케이션의 멀티스테이지 Dockerfile 및 최적화된 빌드 구성 스크립트 작성 | DevOps/환경 구성 능력 |
